Navigation Map

Found during this PR's audit, fixed as part of it: the enterprise-family nav had already diverged into two different shapes. enterprise-homepage.html and enterprise-pricing.html shared one 7-link nav (Platform / Threat Intelligence / Developers / Documentation / Research / Pricing / Enterprise — no Trust Center). enterprise-compliance.html and developer-portal.html shared a different 6-link nav (Platform / Threat Intelligence / Developers / Pricing / Trust Center / Enterprise — no Documentation or Research). Trust Center was added to the two newer pages' own nav when each was built (PR-7, PR-8) but never back-ported to the two older pages, whose primary nav only ever received the Trust Center link in their footer, not their header. This PR unifies all 5 pages (this page included) onto one identical primary nav, replacing the "Documentation"/"Research" top-nav links on the two older pages with "Trust Center" and "Knowledge Center" — nothing becomes unreachable, since /docs/ and /blog/ remain linked from every page's footer and from this page's own Documentation Index and Search Hub.

Two further, pre-existing gaps disclosed rather than silently patched:

The rest of the site does not yet link back

index.html and five legacy pages — pricing.html, trust-center.html, api-docs.html, onboarding.html, get-api-key.html — contain no link to any of the 5 enterprise-family pages. Each enterprise-family page's own guide already disclosed this individually; this is the first place it is stated once, for the whole family. Not fixed here: none of those 6 files is touched by this PR (index.html is a protected live dashboard; the other 5 are real, live, functioning pages with no defect evidence requiring a change).

The canonical component reference documents a different nav than the one actually shipped

components/header.html and components/navigation.html (the PR-4 "single source of truth" reference markup) document a 9-link nav: Products, Threat Intelligence, API, Documentation, Research, Pricing, Enterprise, Blog, Contact. Five of those nine targets — /products.html, /api.html, /docs.html, /research.html, /contact.html — do not exist anywhere in this repository, and its /index.html#threat-intelligence link targets an anchor that does not exist in index.html either. This is a pre-existing inconsistency in the component library itself, found during this PR's audit, not introduced by it, and not corrected here (editing the canonical component reference is an architectural event, not a page-addition task — see the Rollback Guide).
