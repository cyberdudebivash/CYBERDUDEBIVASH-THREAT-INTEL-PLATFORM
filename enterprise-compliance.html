Enterprise Security Overview

How the Platform Is Secured

Core controls in production today.

🔑

Authentication & API Keys

JWT-based access tokens and scoped, tier-based API keys with configurable expiry and revocation.

🔒

Transport Security

HSTS enforced on every response, with a Content-Security-Policy applied to HTML report pages.

🔐

Brute-Force Protection

5 failed login attempts trigger an automatic 15-minute IP lockout on the authentication endpoint.

🔍

Audit Logging

Authentication

Authentication

Every request is authenticated by a JWT access token or an API key. Tokens carry a configurable expiry and can be revoked; API keys are scoped to a subscription tier and can be issued, rotated, or expired independently. Repeated failed login attempts trigger an automatic, time-limited IP lockout.

Responsible Disclosure

Responsible Disclosure Policy

Do not report security vulnerabilities through public GitHub issues, PR comments, or public forums. Report privately by email so a fix can ship before details become public.

No formal bug bounty program exists at this time. Researchers who responsibly disclose a vulnerability are acknowledged publicly on request and may receive service credits.

FAQ

Frequently Asked Questions

Do you have a bug bounty program?

Not a formal one at this time. Responsible disclosures are acknowledged publicly on request and may receive service credits.

What's your incident response SLA?

P0 (critical outage or breach): 15-minute initial response, 2-hour resolution target. See the full severity table above.

Is a Data Processing Agreement available?

Yes — a standard DPA template is available, covering GDPR-style data subject rights and jurisdiction-specific addenda.

Are you SOC 2 or ISO 27001 certified?

Not yet certified by either. Platform architecture is aligned with SOC 2 trust service criteria and ISO 27001 Annex A controls, with certification work in progress — see the compliance status on the existing Trust Center and security & compliance pages for current status.

How do I report a vulnerability?

Email security@cyberdudebivash.com — never a public GitHub issue. See Vulnerability Reporting above for what to include.

Questions for Procurement or Security Review?

Security reports go to security@cyberdudebivash.com. Everything else — procurement, MSA, and enterprise onboarding — goes to our enterprise team.
