Section 02
Security Questionnaire — Pre-filled Responses
Standard CAIQ / SIG Lite / NIST-aligned security questions, answered from the controls the platform implements today (reviewed 2026-10-01). Confirm any answer you rely on with bivash@cyberdudebivash.com.
QuestionResponse
ACCESS CONTROL
Does the platform support role-based access control (RBAC)? ⚡ PLAN-BASED
Access is scoped by plan (FREE, PRO, Enterprise, MSSP) for each API key and session token, and each MSSP key manages only its own client tenants. There are no user accounts or custom roles today.
Is multi-factor authentication (MFA) supported? ✗ NO
Not currently offered. There are no password-based user accounts: access is by API key, or by a 24-hour session token issued for a key. Admin routes require a separate admin secret.
Are API keys scoped and revocable? ✓ YES
Keys are scoped by plan; there are no per-key custom scopes and no IP allowlisting. Keys can be rotated or revoked at any time, and the change reaches every Cloudflare location within about a minute.
Is SSO / SAML 2.0 supported for Enterprise accounts? ✗ NO
SSO (SAML 2.0 / OIDC) is not currently offered, and no delivery date is committed.
DATA SECURITY & ENCRYPTION
Is data encrypted in transit? ✓ YES
HTTPS only, terminated at Cloudflare's edge, with HSTS (max-age=63072000; includeSubDomains; preload). The minimum TLS version follows the Cloudflare zone setting.
Is data encrypted at rest? ✓ YES
Data in Workers KV and R2 is encrypted at rest by Cloudflare. API keys are kept as raw key records in Workers KV (not hashed by the platform), so treat every key as a secret.
Does the platform store customer-uploaded data? ✓ LIMITED
SENTINEL APEX is primarily a read/API platform. Customer data stored is limited to: customer email (as the customer ID), API key records (plan and status), payment-provider order references, and optional webhook configurations. No customer threat data is stored unless explicitly submitted.
What is the key management practice? API keys are 160-bit random values stored as raw records in Workers KV, encrypted at rest by Cloudflare, and shown in audit logs only as a 12-character prefix. Webhook configurations are stored in Workers KV with the same at-rest encryption; the platform adds no envelope encryption or scheduled key rotation.
VULNERABILITY MANAGEMENT
Is there a vulnerability disclosure / responsible disclosure policy? ✓ YES
Report to bivash@cyberdudebivash.com (security.txt, RFC 9116). We acknowledge within 2 business days and give a triage outcome within 7 business days; see the disclosure policy on security-compliance.html. No bug bounty.
Is dependency scanning performed in CI/CD? ✓ YES
Pull requests run secret scanning (TruffleHog, GitGuardian) and a SAST gate (Bandit, Semgrep, Safety and pip-audit for Python dependencies); Dependabot raises GitHub Actions updates. Findings are reported on the pull request.
Is there a penetration testing schedule? ✗ NONE
No third-party penetration test report is available.
INCIDENT RESPONSE
What is the incident notification SLA for Enterprise customers? ⚡ PARTIAL
Contracted incident response: 48h email (PRO), 4h email/chat (Enterprise), 1h dedicated (MSSP), per sla.html. A separate notification commitment for security incidents affecting customer data is not yet published; ask bivash@cyberdudebivash.com.
Is there a documented incident response plan? ⚡ PARTIAL
Production incidents are investigated and recorded as written root-cause reports in the public repository (docs/incidents/). A formal incident response plan document is not published.
LOGGING & MONITORING
Are API access logs available to customers? ✗ NO
Per-request access logs are not exposed to customers. Admin actions, key-lifecycle events and authenticated requests are written to an audit log kept for 30 days and available to the operator.
Is there centralized log aggregation and anomaly detection? ⚡ PARTIAL
Audit events and authentication failures are recorded, and an IP is locked out for 15 minutes after 5 failed key attempts. There is no automated anomaly detection or geographic alerting.
SUPPLY CHAIN & THIRD PARTIES
What third-party services process customer data? Sub-processors are listed on security-compliance.html (hosting, email, contact forms, and payments through Razorpay and Gumroad). Card data is handled by Razorpay or Gumroad and never reaches the platform. No customer intelligence data is shared with third parties.
Are third-party threat intelligence sources vetted? ✓ YES
Sources are registered in the source fabric and health-probed on every publisher run; stale or failing sources are flagged by the stale-source guard, and published items pass IOC artifact rejection and confidence checks before release.
